# Deploying to Railway — Full-Stack Guide

This guide walks you through deploying the **SK Decor Studio - Inventory & Sales Management System** (Laravel 11, React 19 SPA, and MySQL 8.0) to [Railway](https://railway.app).

---

## Why Railway?

- **Native MySQL 8.0**: Unlike some cloud providers that only offer PostgreSQL, Railway has first-class support for native MySQL 8.0 (which matches the exact database design and migrations of this project).
- **Zero-Config Fullstack Container**: The unified root `Dockerfile` packages both the React 19 frontend and the Laravel 11 backend together, so you only need **one application service** + **one MySQL database**.
- **No CORS Issues**: Because the frontend SPA and backend API are served on the exact same domain, authentication cookies and tokens work smoothly without cross-origin configuration.

## Step-by-Step Deployment Guide

### Step 1: Push Latest Changes to GitHub
Ensure you have the latest Railway configuration pushed to your GitHub repository:
```bash
git add .
git commit -m "Configure Railway deployment with MySQL auto-discovery"
git push origin main
```

---

### Step 2: Create a New Project on Railway
1. Log in to your [Railway Dashboard](https://railway.app/dashboard).
2. Click **+ New Project**.
3. Select **Provision MySQL**.
   - Railway will immediately provision a dedicated MySQL 8.0 instance.

---

### Step 3: Deploy the Application from GitHub
1. In the same project canvas, click the **+ New** button (or press `Ctrl/Cmd + K` -> **Add Service**).
2. Select **GitHub Repo**.
3. Choose your repository: `sk-decor-studio`.
4. Railway will automatically detect `railway.json` and the root `Dockerfile`.

---

### Step 4: Link MySQL to the Application Service
1. Click on your newly created application service in the canvas.
2. Go to the **Variables** tab.
3. Click **Add Variable** or **Add Reference**:
   - Add reference for MySQL connection:
     - Variable Name: `DATABASE_URL` or `MYSQL_URL`
     - Value: Click **Add Reference** and select `MySQL` ➔ `MYSQL_URL` (resolves to `${{MySQL.MYSQL_URL}}`).
   - Add the following production variables:
     | Key | Recommended Value | Notes |
     | :--- | :--- | :--- |
     | `APP_ENV` | `production` | Enables production optimizations |
     | `APP_DEBUG` | `false` | Disables verbose debug stack traces |
     | `RUN_MIGRATIONS_ON_BOOT` | `true` | Automatically executes migrations on deploy |
     | `RUN_SEEDER` | `true` | Seeds default admin and catalog data on first run |
     | `APP_KEY` | *(leave blank or set 32-char key)* | Auto-generated by entrypoint if empty |

> [!TIP]
> The backend startup script in `entrypoint.render.sh` automatically detects Railway's `MYSQL_URL`, `MYSQLHOST`, `MYSQLPORT`, `MYSQLUSER`, `MYSQLPASSWORD`, and `MYSQLDATABASE` variables, so connecting takes zero manual string editing.

---

### Step 5: Generate a Public Domain
1. In your application service, click the **Settings** tab.
2. Scroll to the **Networking** section.
3. Click **Generate Domain** (or attach your own custom domain).
   - Railway will assign a public URL like: `https://sk-decor-studio-production.up.railway.app`.

---

### Step 6: Verify Deployment

1. Go to the **Deployments** tab and click on the active deployment to view live build and runtime logs.
2. Look for the startup banner:
   ```text
   ==========================================================
    Starting SK Decor Studio Backend on Render / Railway
   ==========================================================
   ==> Detected Railway MySQL service...
   ==> Creating storage symbolic link...
   ==> Running database migrations...
   ==> Running database seeders (admin & initial catalog)...
   ==> FrankenPHP listening on port 8080...
   ```
3. Once the health check at `/up` passes, click your generated domain. The React POS / Inventory dashboard will load!

## Persistent Storage for Uploaded Images

Railway containers have ephemeral disks by default. For permanent image storage, you have two options:

### Option A: Railway Persistent Volume
1. In Railway, click on your application service.
2. Go to the **Settings** tab ➔ **Volumes**.
3. Click **Add Volume**.
4. Set the Mount Path to `/app/storage`.
   - All uploaded product images and generated PDFs will persist across deployments.

### Option B: Cloudflare R2 / AWS S3
Configure in your application service Variables:
```ini
FILESYSTEM_DISK=s3
AWS_ACCESS_KEY_ID=your_r2_access_key
AWS_SECRET_ACCESS_KEY=your_r2_secret_key
AWS_DEFAULT_REGION=auto
AWS_BUCKET=inventory-uploads
AWS_ENDPOINT=https://<your_account_id>.r2.cloudflarestorage.com
AWS_URL=https://<your_public_domain_or_subdomain>
AWS_USE_PATH_STYLE_ENDPOINT=true
```

## Troubleshooting & Maintenance

### Running Artisan Commands in Railway
1. Click on the application service in Railway.
2. Go to the **Shell** tab.
3. You can execute any Laravel CLI command directly:
   ```bash
   php artisan migrate:status
   php artisan db:seed --force
   php artisan cache:clear
   ```
